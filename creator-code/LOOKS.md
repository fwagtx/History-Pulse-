# The new looks

The daily videos used to share one style: neon glow, big type, a skin in the middle. The new
looks draw each video type as something a person made: a scrapbook page, a trading card, an
airport departures board. Each look changes only the picture. The facts, the titles, the
captions and the posting are exactly the same as before.

**USE CODE: BAD** is on screen in every frame of every look, in the channel's lime, and it
is big: "BAD" is at least 110 px tall in a 1920 px video.

## How a look goes live

A look is switched on only after full-length videos made on GitHub with real Fortnite art have
been checked frame by frame:

- the code is readable in every frame
- the first frame works as a thumbnail
- nothing is cut off or covered, even with the longest names
- nothing important sits where any app's buttons, header or caption go (TikTok, Instagram,
  YouTube Shorts and Facebook all cover the edges; see "Fitting every app" below)
- the pacing feels right, with no empty frames
- the length is 62–90 seconds

To switch a look on or off, set its entry in `creator-code/looks.json` to `true` or `false`
and push. The next nightly build uses it. Videos that are already built and scheduled keep the
look they were built with until they are rebuilt.

If a look ever fails on a day's data, that video is drawn in the classic look instead (the
GitHub run shows a warning), so a look can never cost a video.

## Fitting every app

Each video posts to TikTok, Instagram Reels, YouTube Shorts and Facebook Reels, and each app
draws its own buttons and text over the picture: a header across the top, the like/comment/share
buttons down the right side, and the name, caption and audio line across the bottom. So every
look and every classic format keeps its text, its cosmetics and the USE CODE: BAD element inside
the part of the frame none of them covers (1080x1920 video):

- from x 60 to x 1020 between y 230 and y 740
- from x 60 to x 900 between y 740 and y 1420 (the buttons run down the right side below that)
- on the first frame, which is also the cover, text starts at y 285 or lower, because
  Instagram's profile grid crops the cover to 4:5

Backgrounds and decoration can still fill the whole frame. `scripts/cc_safe.py` holds these
numbers and checks every video in the browser that renders it; the nightly builds run the check
on each video, record it in the release's manifest (`safe_zones`), and if a look ever fails it
the classic version of that format is used instead. The preview harness writes `apps.jpg`, key
stills under each app's buttons and captions, for a quick look.

## Trying a look without switching it on

Preview builds go to `preview-...` releases, which nothing schedules or posts:

- Quiz videos: run the **Quiz videos** workflow with `from`, `days` and `looks` (for example
  `on_this_day`, or `all`). The videos go to `preview-quiz-DATE`.
- Shop videos: run the **Daily shop video** workflow with `formats` (for example `og_check`)
  and `looks`. The videos go to `preview-shop-DATE`.

On a computer, `scripts/cc_look_preview.py` renders one video with the looks on, plus stills,
a contact sheet and a check of how much of the lime code is visible in each still.

## Where things are

- `scripts/cc_looks.py`: the switches and the shared kit (textures, marker strokes, write-on
  text, sticker cut-outs, text that shrinks to fit)
- `scripts/cc_look_<name>.py`: one file per look
- `creator-code/assets/fonts/`: the fonts the looks use (Google Fonts, open licence, see
  `OFL.txt`)
- `creator-code/assets/textures/`: paper, cork, wood and so on, all generated by
  `scripts/cc_textures.py` (no stock images)
